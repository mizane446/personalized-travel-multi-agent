# Hermes 旅行增强迁移计划 v1

日期：2026-10-18。状态：官方源码已克隆；本文为迁移计划，功能尚未迁移。

## 目标与已确认设计

在官方完整源码和原生 Desktop 上实现旅行增强：主 Agent 通过 Hermes 原生委派启动子 Agent，子 Agent 仅调用豆包搜索；逐项迁移人物偏好 Wiki、审查、方案与导出，复用原生观测接口。增强功能独立成模块，只有确认扩展点无法满足需求时才最小修改上游文件。

设计依据为用户本次确认的“干净克隆官方源码、独立模块实现增强、保留官方桌面、提供原版与增强对照”。本轮仅完成克隆与计划，不安装运行环境、不迁移业务、不调用付费 API。

## 文件和维护方式

上游源码继续保留原目录。计划将自有源模块集中在根目录 `travel_extensions/` 下，作为独立插件源包维护，经官方安装接口加载；这个目录名本身不构成自动加载约定。首次实现前用最小插件验证加载与 profile 隔离。

拟拆分为 `doubao_search/`（供应商接口适配）、`travel/`（旅行规则、审查与方案）、`wiki/`（偏好记忆）。是否合并插件包，以新版插件协议和依赖边界验证结果决定，不为目录整齐增加适配层。自有测试与各模块同目录维护；涉及上游修改时补对应上游测试。

不把第三方产品直接塞进上游核心工具目录；Langfuse 使用独立官方目录清单来源。保留上游 LICENSE、NOTICE、AGENTS 和原始历史，不将官方功能标为自研。

README 保留官方介绍，追加旅行增强入口、进度和选型表。本文维护迁移任务；后续 `改进说明.md` 维护实现对照，避免多个文件重复维护状态。

## 阶段 1：豆包搜索 provider

- [ ] 明确豆包搜索具体产品与接口：搜索 API、模型联网工具或其他已授权接口不能混称；核查官方请求/响应、鉴权、价格和来源字段。
- [ ] 先检查新版内置 provider 是否已有可复用支持，再按 `WebSearchProvider` 和 `ctx.register_web_search_provider()` 接入缺口。
- [ ] 最小实现 `search(query, limit)`，归一化标题、URL、摘要；配置原生 `web.search_backend`。不臆造链接，不默认打开其他搜索后端。
- [ ] 先写契约失败测试，覆盖正常结果、空结果、鉴权失败、429、超时、缺来源和异常响应；无密钥时报告不可用，不触发网络探测。
- [ ] 使用隔离 profile 运行官方插件 validate/doctor 和一次低成本真实搜索。费用无法合理估价或累计超出授权时先确认，不复制旧项目凭据到公开文件。

验收：原生 `web_search` 确实调用豆包，来源完整、错误可解释、日志不暴露密钥。尚未确认 API 之前不承诺具体 SDK、字段或固定费用。

## 阶段 2：原生子 Agent 最小旅行链路

- [ ] 先用单子任务贯通主 Agent → 原生委派 → 豆包搜索 → 交回；再验证 food/hotel/attraction 最多三方向并发。
- [ ] 用程序侧配置限制子 Agent 的实际工具集合，仅允许所需搜索；禁止再次派发、终端、文件和无关 MCP。测试继承父工具、自动保留 MCP 及恢复后的权限路径。
- [ ] 复用原生取消、超时、完成通知和并发限制；只补旅行任务的必要上下文与人物/会话绑定。
- [ ] 测试部分成功、取消后迟到结果、重复通知、用户改变需求后旧结果隔离，以及跨 profile/session 不串任务。
- [ ] 原项目每任务五次搜索和最多两轮修正作为待迁移业务规则：先核查原生预算能否覆盖，再补无法覆盖的计数；重试不得绕过上限。

验收：无 Claude Code 安装也可完成整条搜索链路；权限测试通过。高德不作为依赖，不迁移旧高德入口。官方源码自身的无关第三方集成不做全仓删除。

## 改进文档模板

每项改进写明：原版能力 → 具体缺口 → 复用接口与版本 → 新增文件 → 原文件修改位置 → 完整源码与 diff → 行为示例 → 验证与限制。

- 原版完整文件：链接到固定上游 commit，而非浮动 main。
- 增强后完整文件：链接到本地增强文件，发布后链接到对应增强 commit。
- 新增文件：说明原版不存在，不能编造“原代码”。
- 精确改动：`git diff travel-upstream-baseline-20261018 -- <文件>`。
- 只配置官方能力时标记为“配置接入”，不声称重新实现。
- 不在 Markdown 中重复粘贴成千行完整源码；完整文件与逐行 diff 均可查看，解释集中维护。
